The eight migration strategies

StrategyIn plain wordsContoso example (fictional)
RetireTurn off what no longer adds business valueOld fax gateway
RehostLike-for-like move. Only if it won't need changes for 2+ yearsReporting server
ReplatformModern hosting platform, minimal code changesContoso Shop → App Service
RefactorBetter code structure, no new featuresOrder API clean-up
RearchitectRedesign the architecture for scale and agilitySplit the order monolith
ReplaceUse a commercial SaaS product insteadHR portal
RebuildFully redevelop it as cloud-nativeLoyalty app, version 2
RetainKeep it where it is, for nowWarehouse scanner system
Learn: "Each workload can be Retired, Retained, Rehosted, Replatformed, Refactored, Rearchitected, Rebuilt, or Replaced."

Animated architecture (text version)

From inventory to decisions

  1. Discover: Azure Migrate finds servers, apps and dependencies. Learn: its discovery is free.
  2. Assess: full visibility into every component, dependency and requirement.
  3. Old fax gateway: no business value left → Retire.
  4. Reporting server: no changes needed for two years or more → Rehost.
  5. Contoso Shop: a modern platform with minimal code changes → Replatform to App Service.
  6. HR portal: a SaaS product does the job → Replace.
  7. Warehouse scanners must stay on site → Retain, for now.
  8. Prioritize into migration waves. Learn: start with simpler workloads to reduce risk.

✎ Workload names and choices are Contoso's (fictional). The strategies and steps come from Learn.
