Infrastructure as code and a safe slot swap

  1. A change is merged. The pipeline builds and tests it automatically.
  2. Infrastructure as code (Bicep) applies the desired state, then the app deploys to the staging slot.
  3. App Service warms up each staging instance with a request to the app root before the swap.
  4. Health checks pass, so swap: the slots switch routing rules and no requests are dropped.
  5. Shoppers get the new version while Application Insights watches it.
  6. Something's wrong? Swap the same two slots again. That's an immediate rollback.
Sources on Microsoft Learn: Architecture strategies for using infrastructure as code (updated 2026-11-04) · Architecture strategies for safe deployment practices (updated 2026-06-17) · Set up staging environments in Azure App Service (updated 2025-11-28)

DewiDeploy to staging, warm it up, check its health, then swap. And if something's wrong, swap straight back!

Checkpoint: A bad release reached production through a slot swap. What's the fastest rollback?
  • Rebuild the server by hand
  • Swap the same two slots again
  • Delete the App Service plan

Answer: Swap the same two slots again. Learn: you can restore the slots to their pre-swap states by swapping the same two slots immediately.
