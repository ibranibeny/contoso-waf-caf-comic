Animated architecture (text version)

Baseline web app: one public door

  1. A shopper connects over HTTPS to Application Gateway, the single public entry point. Its TLS certificate lives in Key Vault.
  2. An attacker sends a SQL injection. In Prevention mode, the WAF blocks attacks its rules detect.
  3. A private DNS zone resolves the App Service name to its private endpoint, and the gateway forwards the request privately.
  4. App Service reads a secret from Key Vault: DNS returns the private endpoint IP, and a managed identity proves who's asking.
  5. Orders go to SQL Database and files to Storage, each through a private endpoint.
  6. A direct call from the internet to the database? SQL Database, Storage and Key Vault all block public access.

✎ Simplified from Learn's "Baseline highly available zone-redundant web application": the private endpoints of Key Vault, SQL Database and Storage appear as labels on the arrows, and App Service's VNet integration subnet isn't drawn.

Checkpoint: In the baseline web app, how does App Service reach Azure SQL Database?
  • Over the public internet, with a firewall rule
  • Through VNet integration and a private endpoint, resolved by a private DNS zone
  • Through Azure Bastion

Answer: Through VNet integration and a private endpoint, resolved by a private DNS zone. Outbound flow: VNet integration routes the call, the linked private DNS zone returns the private endpoint IP, and the virtual network delivers it through the private endpoint.
