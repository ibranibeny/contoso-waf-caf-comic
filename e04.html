📍 The sky harbor · central hub

A harbor needs roads. In Azure, the roads are virtual networks.

BayuThe most common shape is hub-and-spoke. Shared services live in the hub virtual network. Each workload gets its own spoke, peered to the hub.

DewiLike our harbor: a hub in the middle, docks around it.

Ready · network topology

What lives in the hub?

  • Azure Firewall: inspects traffic and is the primary egress point from the spokes to the internet.
  • VPN Gateway or ExpressRoute gateway: connects Azure to on-premises.
  • Azure Bastion: secure remote access to VMs.
  • Azure DNS Private Resolver: hybrid name resolution, with inbound and outbound endpoints.
  • One DDoS Protection plan, deployed in the connectivity subscription.
The hubs live in the Connectivity subscription (Platform → Connectivity management group). Peering isn't transitive, so spoke-to-spoke traffic needs routes through the firewall, or direct peering.

Hub-and-spoke: who talks to whom

  1. On-premises users call the Order API: through the VPN/ExpressRoute gateway, inspected by Azure Firewall, into spoke A.
  2. Spoke A calls the reporting VM in spoke B. Peering isn't transitive, so user-defined routes send it through the firewall.
  3. Spoke B goes out to the internet. Azure Firewall is the primary egress point.
  4. Admins connect through Azure Bastion: RDP or SSH over private IPs, so the VMs need no public IP.
  5. Hybrid DNS: the DNS Private Resolver forwards queries for on-premises names toward on-premises DNS.

✎ Learn: don't deploy Layer 7 inbound appliances such as Application Gateway as a shared hub service. They belong in the workload's spoke.

Subscription vending

  1. The shop team asks for a subscription: budget, owners, networking needs, criticality, confidentiality.
  2. Business logic and approval come from the Cloud Center of Excellence.
  3. The request pipeline writes a parameter file (JSON, YAML or TFVARS) and opens a pull request.
  4. Merging triggers the deployment pipeline, which runs the Bicep or Terraform vending module.
  5. A new subscription is created and placed in the right management group, so it inherits policy.
  6. Then: a virtual network peered to the hub, access for the team, and a preliminary budget.
  7. Hand-off. The workload team deploys and operates, and keeps the budget current: budgets aren't hard limits.

✎ A synthesis of Learn's CAF and Architecture Center vending pages. Your platform team's tooling may differ.

Checkpoint: In a hub-and-spoke design, where does traffic from a spoke go when it heads to the internet?
  • Straight out of each spoke's own public IP
  • Through Azure Firewall in the hub, the primary egress point
  • Through Azure Bastion

Answer: Through Azure Firewall in the hub, the primary egress point. The hub firewall sits between every spoke and the internet, on-premises and other spokes routed through it.
