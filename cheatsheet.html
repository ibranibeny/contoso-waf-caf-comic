Ready

Azure landing zone

Two parts

  • Platform landing zone: the centralized foundation for governance, security and shared resources. Usually one per Microsoft Entra tenant. Run by the platform team.
  • Workload landing zones (formerly "application landing zones"): where workload teams deploy and run workloads inside the platform's guardrails.

Eight design areas

  • Azure billing and Microsoft Entra tenant
  • Identity and access management
  • Resource organization
  • Network topology and connectivity
  • Security
  • Management
  • Governance
  • Platform automation and DevOps

Management groups

  • Tenant root group → intermediate root (e.g. Contoso)
  • Platform: Identity, Management, Connectivity, Security
  • Workload landing zones (older pages: "Landing zones"): Corp (needs the corporate network through the hub), Online (may need direct internet traffic), Local (Azure Local)
  • Sandbox: isolated, less restrictive policies
  • Decommissioned: canceled landing zones, deleted after 30–60 days

Hub-and-spoke

  • Hub: Azure Firewall, VPN or ExpressRoute gateway, Azure Bastion, DNS Private Resolver; one DDoS plan in the connectivity subscription
  • Peering isn't transitive: route spoke-to-spoke traffic through the firewall
  • Application Gateway belongs in the workload's spoke, not the shared hub
  • Azure Virtual WAN: a Microsoft-managed hub alternative

Five pillars

PillarDesign principlesChecklist
ReliabilityDesign for business requirements · Design for resilience · Design for recovery · Design for operations · Keep it simpleRE:01–RE:10

Reference architecture

Baseline zone-redundant web app, in brief

  • Application Gateway with Web Application Firewall is the single public entry point
  • App Service across availability zones, reached through a private endpoint
  • SQL Database, Key Vault and Storage reached over private endpoints, with public access blocked; private DNS zones resolve the names
  • Managed identities instead of secrets in code; Application Insights and Azure Monitor for observability
  • Deployment slots for safe releases; infrastructure as code for repeatable environments
